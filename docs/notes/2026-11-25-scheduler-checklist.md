## 1. Блокеры релиза

- [ ] **Права на lock-файлы [проверено].** Cron (root) создаёт `var/*.worker.lock` с `0644`,
  у `www-data` `fopen('c')` не открывается, `workerLock()` возвращает `false`, воркер молча выходит.
  - [ ] Запускать cron-задания от `www-data` (предпочтительно) или создавать lock с `0666`
  - [ ] Если от `www-data`: проверить, что ему доступны запись в лог контейнера (`/proc/1/fd/1`), `var/` и uploads
  - [ ] При старте контейнера исправлять владельца уже созданных root файлов в `var/`
        (`*.lock`, база, логи, кеш)
  - Готово, когда: после запуска задачи из cron та же задача запускается из админки, и наоборот.
- [x] **Ошибка открытия не равна «занято» [по коду].** `workerLock()` отдаёт `false` в обоих случаях,
  поэтому `workerIsRunning()` считает недоступный файл живым воркером и зависшая задача не снимается.
  - [x] Писать в лог ошибку открытия и отличать её от занятой блокировки
  - Готово, когда: файл без прав даёт запись в логе, а не тихий выход.
- [x] **Cron-lock переживает задание [проверено].** Его наследует дочерний `task_worker`, `fclose()` родителя не снимает.
  - [x] `flock($lock, LOCK_UN)` перед `fclose()` в `bin/cron_worker.php`
  - [x] Режим `'ce'` (close-on-exec) в `fopen` там же и в `AbstractTask::workerLock()`
  - Готово, когда: задание завершилось, дочерний воркер ещё работает, а `flock -n var/cron-*.lock true` успешен.
- [x] **Недоступный cron-lock [по коду].** При `$lock === false` задание сейчас идёт без блокировки.
  - [x] Предупреждение в лог, задание запускается без блокировки (пропуск навсегда хуже)
